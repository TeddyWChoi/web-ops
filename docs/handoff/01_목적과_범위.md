# 01. 목적과 범위

## 만드는 이유

서비스개발실에는 웹기획자가 없습니다. 그래서 웹 작업마다 아래 문제가 반복됩니다.

- 누가 요청하고, 누가 결정하고, 누가 검수하는지가 프로젝트마다 다르고 문서로 남지 않음
- 요청이 정리되지 않은 채 내려와서 작업 중간에 방향이 바뀜 (예: 스포2 사전예약은 휴대폰 번호 수집이라는 핵심 변경이 요청에 빠져 있었음)
- 같은 결과물을 여러 사람에게 따로 검수받아 수정 의견이 여러 번 나뉘어 들어옴
- 실무자끼리 일정을 바꾸고 결정권자가 나중에 알게 됨 (예: 클로저스 오픈 일정 변경)
- 여러 게임의 웹 작업이 겹칠 때 우선순위를 정할 사람이 없음
- 일정과 진행 상황을 한눈에 볼 자료가 없어서 각 팀이 서로 무엇을 하는지 모름

이 페이지는 웹기획자 역할 중 **절차 안내와 일정 관리**를 문서로 대신합니다. 결정은 각 프로젝트의 결정권자가 하고, 페이지는 누가 무엇을 언제 해야 하는지를 보여줍니다.

## 작성자의 위치

- 작성자(테디 팀장, 디자인팀)는 결정권자가 아닙니다. 웹 업무 전반을 파악하고 가이드를 주는 역할입니다.
- 페이지에서도 작성자가 결정하는 것처럼 보이는 표현은 피합니다. "○○ 팀장이 확정", "PM이 진행"처럼 실제 주체를 적습니다.
- 사람에 대한 평가는 넣지 않습니다. 문제는 구조(창구, 단계, 기록 부재)로 적습니다.

## 범위

**포함**
- 서비스개발실이 맡는 모든 웹 작업: 게임별 공식 홈페이지, 사전예약·이벤트·프로모션 페이지, 플랫폼(파파야플레이 등) 웹 작업
- 웹 작업의 요청 → 기획 → 디자인 → 개발 → 검수 → 오픈 흐름
- 프로젝트별 담당, 일정, 결정 기록, 미결 사항
- 프로젝트 간 일정 충돌과 인력 겹침

**제외**
- 게임 클라이언트, 인게임, 서버 인프라 일정 (웹과 맞물리는 지점만 적음)
- 사업 지표, 매출, 인사 관련 내용

## 스포2 페이지와의 차이

| 항목 | 스포2 페이지 | 새 페이지 |
|---|---|---|
| 대상 | 프로젝트 1개 | 서비스개발실 웹 업무 전체 (여러 프로젝트) |
| 가이드 | 스포2 전용 역할·흐름 | 공통 가이드 + 프로젝트별 담당 |
| 일정 | 스포2 간트 1개 | 전체 프로젝트 요약 간트 + 프로젝트별 상세 간트 |
| 추가로 필요한 것 | — | 프로젝트 목록, 인력별 작업 현황, 프로젝트 간 충돌 표시 |

## 성공 기준

- 새 웹 작업이 생기면 누구나 페이지를 보고 요청 창구와 절차를 알 수 있다
- 매주 회의에서 이 페이지를 띄워 놓고 진행 상황을 확인한다
- 결정이 바뀌면 언제 무엇이 바뀌었는지 기록이 남는다
- 한 사람에게 일이 몰리거나 두 프로젝트 일정이 겹치는 것이 미리 보인다
- 프로젝트가 끝나면 그 절차를 컨플루언스에 옮겨 다음 프로젝트에 쓴다
