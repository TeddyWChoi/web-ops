# 02. 페이지 구조

스포2 페이지는 탭 4개(업무 가이드 / 일정표 / 회의록·미결 / 논의 안건)로 구성했습니다. 새 페이지는 여러 프로젝트를 다루므로 "전체 현황"을 맨 앞에 두고, 프로젝트별 상세를 아래 구조로 반복합니다.

## 권장 탭 구성

| 탭 | 내용 | 스포2 페이지 대응 |
|---|---|---|
| 1. 전체 현황 | 진행 중인 프로젝트 목록, 전체 요약 간트, 인력별 작업, 충돌 경고 | 새로 추가 |
| 2. 공통 가이드 | 모든 웹 작업에 적용되는 원칙, 업무 흐름, 상황별 대응, 소통 도구 | 업무 가이드 탭의 공통 부분 |
| 3. 프로젝트별 | 프로젝트마다 팀 구성, 업무별 담당, 상세 간트, 팀별 현황, 세부 일정 | 업무 가이드의 프로젝트 부분 + 일정표 탭 |
| 4. 회의록 · 미결 | 프로젝트별 결정 기록, 미결 사항, 액션 아이템, 회의록 | 회의록·미결 탭 |
| 5. 논의 안건 | 결정이 필요한 안건 (현재 / 문제 / 제안 / 결정) | 논의 안건 탭 |

탭이 많아지면 프로젝트별 탭 안에서 프로젝트 선택(버튼 또는 드롭다운)으로 전환합니다.

## 1. 전체 현황

- **프로젝트 목록 표**: 프로젝트명 / 결정권자 / PM / 웹 담당(기획·디자인·개발) / 다음 마일스톤 / 상태(정상·주의·위험)
- **전체 요약 간트**: 프로젝트마다 한 줄. 핵심 마일스톤(사전예약 시작, 심사, 오픈)만 표시
- **인력별 작업 현황**: 사람마다 한 줄, 맡은 작업을 기간 막대로. 같은 기간에 막대가 겹치면 경고 색
  - 스포2에서 오중수 님 한 명에게 홈페이지·사전예약·플랫폼 연동이 몰린 것이 이 표에서 바로 보여야 함
- **충돌 경고**: 같은 사람·같은 기간에 두 프로젝트가 겹치는 경우, 누가 우선순위를 정하는지 함께 표시

## 2. 공통 가이드

스포2 페이지의 업무 가이드 섹션 중 프로젝트와 무관한 부분을 공통으로 뺍니다.

- **00 이 문서에 대해**: 원칙(결정은 결정권자, 진행은 PM, 실무자끼리 합의로 일정·범위가 바뀌지 않음), 적용 범위, 소통 도구(요청은 지라, 팀 간 소통은 팀즈, 일정 변경·긴급 이슈는 공통 채널)
- **업무 흐름 7단계**: 요청 접수 → 요구사항과 웹기획 → 일정 산정과 확정 → 디자인 → 웹 개발 → 검수 → 오픈과 운영
  - 단계마다 `주관 / 산출물 / 분기 / 지원 / 넘어가는 조건`
  - 1단계 분기: 기존 구조 수정이면 메뉴구조도나 수정 목록으로 바로 디자인, 신규 기능이 들어가면 웹기획부터
  - 2단계 웹기획안 필수 항목: 전체 페이지 목록, 화면별 상태(진행 전·중·완료·종료 후), 사용 흐름, 예외 상황, 개인정보 수집 여부, PC/모바일 차이
- **상황별 대응**: 일정이 밀릴 때 / 수정 요청이 생길 때 / 오픈 직전·직후 긴급 이슈 / 누가 맡을지 애매할 때
- **정기 회의 운영 원칙**: 아젠다 사전 공유, 주간 보고, 회의 내용 정리·공유 담당

## 3. 프로젝트별 (프로젝트마다 반복)

- **팀 구성 카드**: 사람마다 카드 1장. `역할(짧게) / 이름+직함 / 설명 1~3문장`
- **업무별 담당표**: `업무 / 하는 사람 / 확정 / 돕는 사람` 4열
  - "승인"이 아니라 **"확정"**을 씀. 디자인·웹기획처럼 내용 확인만 하는 줄은 "(내용 확인)" 표기
  - 같은 사람이 같은 줄의 하는 사람과 돕는 사람에 동시에 들어가지 않게
- **정기 회의**: 일시, 소집·진행, 회의 내용 정리, 결정, 참석자(직급 순), 고정 안건
- **확인 필요 항목**: 아직 정해지지 않은 담당·일정을 칩으로 표시
- **상세 간트** (04 문서 참고): 마일스톤 행 + 팀별 그룹 + 업무 막대
- **팀별 현황 카드**: 팀마다 `완료 / 진행 중 / 결정 대기 / 다음`, 기준 날짜 표기
- **가장 큰 일정 위험** 박스: 1개만. 무엇이 밀리면 오픈이 밀리는지
- **세부 일정 표**: `날짜 / 내용 / 담당 / 상태`

## 4. 회의록 · 미결

- **미결 사항**: `안건 / 결정할 사람 / 막혀 있는 일` — "막혀 있는 일"이 이 표의 핵심
- **액션 아이템**: `담당 / 내용 / 기한`
- **회의 밖 결정 · 논의**: 날짜별 한 줄 기록. 이전 결정이 바뀌면 이전 줄에 `(MM/DD 변경: …)`를 붙이고 새 줄을 추가 (지우지 않음)
- **회의록**: 날짜별 접이식. `배경 / 결정 / 주요 논의 / 표`

## 5. 논의 안건

- 안건마다 카드: `현재 / 문제 / 제안 / 결정`
- 결정 칸 상태: 완료(초록) / 일부 결정(주황) / 논의 필요(회색)
- 결정된 안건은 결정 내용으로 채우고, 더 볼 필요가 없으면 삭제
- 사람 평가가 드러나는 표현 금지. 사례와 구조로만 적음

## 상태 표기 (페이지 전체 공통)

| 상태 | 의미 | 색 |
|---|---|---|
| 완료 | 끝남 | 초록 |
| 진행 중 | 지금 작업 중 | 파랑 (진한) |
| 예정 | 날짜가 잡힘 | 파랑 (연한) |
| 위험 | 밀리면 오픈에 영향 | 주황 |
| 제안 | 아직 확정 전, 작성자가 잡은 날짜 | 회색 칩 |
| 미정 / 기한 미정 | 날짜 없음 | 회색 글자 |

추정한 기간은 점선 막대로 그려서 확정 일정과 구분합니다.
