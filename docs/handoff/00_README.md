# 서비스개발실 웹 업무 관리 페이지 — 작업 인계 패키지

스포2 한국 런칭 웹 업무 가이드(이하 "스포2 페이지")를 만들면서 정한 구조, 운영 방식, 기술 규칙을 정리한 문서 묶음입니다. 새 채팅에서 서비스개발실 웹 업무 전체를 관리하는 페이지를 만들 때 이 파일들을 첨부해서 시작합니다.

## 파일 구성

| 파일 | 내용 | 새 채팅에서 쓰는 시점 |
|---|---|---|
| `00_README.md` | 이 파일. 패키지 사용법 | 처음 |
| `01_목적과_범위.md` | 페이지가 해결하려는 문제, 범위, 스포2 페이지와의 차이 | 처음 (방향 합의) |
| `02_페이지_구조.md` | 탭, 섹션, 구성 요소 명세 | 페이지 첫 제작 |
| `03_운영_방식.md` | 회의록·결정을 받아 페이지를 갱신하는 절차와 표기 규칙 | 매주 갱신 |
| `04_디자인_기술_규칙.md` | 스타일 토큰, 간트 생성 방식, 자동 오늘 선, 검증 방법 | 페이지 제작·수정 |
| `05_교훈과_체크리스트.md` | 스포2에서 겪은 문제와 프로젝트 시작 시 확인할 항목 | 새 프로젝트 등록 시 |
| `06_시작_프롬프트.md` | 새 채팅 첫 메시지로 붙여넣을 프롬프트와 준비물 | 처음 |
| `reference/sf2-web-guide.html` | 스포2 페이지 원본 (스타일·구조 참고용) | 페이지 첫 제작 |
| `reference/gantt_generator.py` | 간트 차트 생성 스크립트 (스포2 버전) | 간트 제작 |
| `reference/milestone_stagger.py` | 마일스톤 라벨 겹침 방지 스크립트 | 간트 제작 |

## 사용 순서

1. 새 채팅을 열고 이 폴더의 파일을 모두 첨부합니다.
2. `06_시작_프롬프트.md`의 프롬프트를 붙여넣고, 대괄호 부분을 채웁니다.
3. Claude가 `01`~`05`를 읽고 질문하면 답합니다. 특히 관리할 프로젝트 목록과 사람별 역할은 처음에 정확히 줘야 합니다.
4. 첫 버전이 나오면 `05`의 체크리스트로 빠진 항목을 확인합니다.
5. 이후에는 매주 회의 녹음 텍스트나 결정 사항을 주고, `03_운영_방식.md` 규칙대로 갱신하게 합니다.

## 주의

- `reference/sf2-web-guide.html`에는 스포2 내부 정보(인원, 일정, 결정 사항)가 들어 있습니다. 새 페이지에 그대로 옮기지 말고 구조와 스타일만 참고합니다.
- 새 페이지를 팀에 공유하기 전에 공유 범위(조직 내부로 제한)를 먼저 확인합니다.
