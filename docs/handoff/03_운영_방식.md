# 03. 운영 방식

페이지는 한 번 만들고 끝나는 문서가 아니라 매주 갱신합니다. 스포2 페이지를 운영하면서 정한 규칙입니다.

## 역할 분담

| 일 | 담당 |
|---|---|
| 회의 소집, 아젠다 공유, 진행 | 각 프로젝트 PM |
| 회의 내용 정리·공유, 일정표(WBS) 갱신, 주간 보고 | 각 프로젝트 PM |
| 바뀐 역할·절차를 가이드에 반영, 양식 관리 | 테디 팀장 |
| 진행 상황 공유, 서로 빠진 것 확인(크로스 체크) | 각 팀 팀장 |
| 최종 결정 | 각 프로젝트 결정권자 |

회사에 PMO가 없으므로 팀장들이 PMO 역할(산출물이 업데이트됐는지 확인하고 알려주기)을 나눠 맡습니다. 페이지 작성자가 혼자 모든 일정을 갱신하면 다시 "직함 없는 PM"이 됩니다.

## 매주 갱신 흐름

1. **입력 받기**: 회의 녹음 텍스트, PM이 공유한 회의 내용, 또는 말로 전한 결정 사항
2. **분류하기**: 들어온 내용을 아래 다섯 가지로 나눔
   - 결정 → 결정 기록에 날짜와 함께 추가, 관련 표·간트 반영
   - 일정 변경 → 간트와 세부 일정, 팀별 현황 반영
   - 담당 변경 → 팀 구성, 업무별 담당표, 간트 담당명 반영
   - 아직 안 정해진 것 → 미결 사항 또는 논의 안건
   - 할 일 → 액션 아이템
3. **전체 대조하기**: 한 곳을 바꾸면 같은 내용이 들어간 다른 곳도 찾아서 맞춤. 스포2에서 가장 자주 생긴 문제가 "표는 바꿨는데 카드나 간트에는 예전 내용이 남는 것"이었음
4. **확인 요청하기**: 녹음이 깨졌거나 해석이 갈리는 부분은 임의로 채우지 않고 사용자에게 물어봄
5. **게시**: 같은 주소로 다시 게시 (링크 유지)

## 녹음 텍스트를 다룰 때

- 음성 변환 텍스트는 이름과 용어가 자주 깨짐 (예: "인증세가" → "중수가"일 수 있음, "컴플라이언스" → 컨플루언스). 확실하지 않으면 담당자 이름을 붙이지 않고, 녹음에 나온 말 그대로 적은 뒤 확인 필요로 표시
- 원칙을 말한 문장("○○가 하는 게 맞다")과 실제로 정한 문장("그럼 이렇게 하죠")을 구분. 실제 운영 방식은 뒤쪽 문장을 따름
- 같은 날 여러 회의가 있으면 나중 회의 결정이 앞 결정을 바꿀 수 있음 (스포2: 10/12 "김충곤 팀장 단일 창구" → 10/13 "고민제 PM 중심")

## 표기 규칙

- 이름은 처음 정한 표기로 통일: `김충곤 팀장`, `고민제 PM`, 직급이 없으면 이름만
- 참석자는 직급 순 (실장 → 팀장 → PM → 직급 없음)
- "승인" 대신 "확정"
- 결정이 바뀌면 이전 기록을 지우지 않고 `(MM/DD 변경: 새 내용)`을 붙임
- 작성자가 임의로 잡은 날짜는 반드시 "제안"으로 표시하고, 확정되면 표시를 뺌
- 추정 기간은 점선 막대
- 설명조 문장(섹션 첫머리 안내 문구, "~를 정리했습니다")은 넣지 않음. 표와 규칙만
- 양식 섹션은 넣지 않음. 요청 양식은 지라에 맞추고, 필요한 항목은 업무 흐름 안에 적음

## 넣지 않는 것

- 특정인의 역량·태도에 대한 평가, 인사·채용 이야기
- 건강, 개인 사정 같은 사적인 이유 (연차는 "연차"까지만)
- 확정되지 않은 사람 배정을 확정처럼 적는 것

## 공유

- 처음 만들면 비공개. 팀에 공유하기 전에 공유 범위를 조직 내부로 제한
- 보고 순서: 작성자의 직속 상사 → 관련 팀장(옆 팀은 "제안" 형태로) → 정기 회의에서 전체
- 프로젝트가 끝나면 페이지 내용을 컨플루언스로 옮겨 사내 자산으로 남김

## 매주 확인 체크리스트

- [ ] 오늘 선과 팀별 현황 기준 날짜가 맞는가
- [ ] 이번 주 결정이 결정 기록, 관련 표, 간트에 모두 반영됐는가
- [ ] 미결 사항 중 결정된 것을 뺐는가
- [ ] 액션 아이템 기한이 지난 것이 있는가
- [ ] "제안" 표시 중 확정된 것을 바꿨는가
- [ ] 한 사람에게 같은 기간 작업이 몰리지 않았는가
- [ ] 담당이 비어 있는 작업이 없는가
